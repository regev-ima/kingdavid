# מרכז שליטה שיווקי — תוכנית עבודה

> מסמך תכנון. המטרה: להפוך את `דשבורד שיווק` הקיים למרכז שליטה אחד שעונה בתוך שניות על
> ארבע שאלות — כמה הוצאתי, מה קיבלתי, מה נמכר ומאיזו מודעה, ואיפה להגדיל ואיפה לעצור.

---

## 1. מה המשמעות של הבקשה

הבקשה נשמעת כמו "מסך", אבל היא בפועל **בניית שכבת נתונים שיווקית** שלא קיימת היום.
המסך הוא ~20% מהעבודה. 80% הם:

| שכבה | מה זה אומר | קיים היום? |
|---|---|---|
| **הוצאות** | משיכה אוטומטית של Spend מ-API של Meta / Google / TikTok, ברמת מודעה, ליום | ❌ אין |
| **Attribution** | לכל ליד לדעת פלטפורמה → חשבון → קמפיין → Ad Set → מודעה | 🟡 השדות קיימים ב-DB, לא מנוצלים |
| **חיבור למכירות** | ליד → הצעה → עסקה → סכום, מיוחס אחורה למודעה | ✅ קיים ועובד |
| **אגרגציה** | RPC שמחזיר שורות בכל אחת מ-4 הרמות עם 15 מדדים | 🟡 קיים ל-2 רמות בלבד (מקור, קמפיין) |
| **UI** | KPI, טבלה, Drill Down, פילטרים, השוואת תקופות | 🟡 חלקי |
| **דיווח חזרה** | שליחת אירועי CRM חזרה ל-CAPI / Offline Conversions | ❌ אין בכלל |

**נקודת המפתח:** בלי שכבת ההוצאות, כל המדדים הכספיים (CPL, CAC, ROAS, MER, רווחיות)
הם אפס מתמטי. זו הבעיה הכי גדולה היום ולא רואים אותה, כי המסך פשוט מציג ₪0.

### מה עובד
- טווחי תאריכים: היום / אתמול / השבוע / החודש / 7 / 30 / 60 / 90 / השנה / מותאם
- קיבוץ לפי **מקור** ולפי **קמפיין**, עם לידים, סגירה, בטיפול, אבד

- הרשאות: אדמין בלבד (`canAccessAdminOnly`)

### 🔑 הגילוי הכי חשוב — ה-Attribution כבר במסד הנתונים
טבלת `leads` **כבר מכילה** את כל השדות שנדרשו בסעיף 2 של הבקשה
(`src/constants/leadMarketingFields.js`):

```
utm_source · utm_medium · utm_campaign · utm_content · utm_term · click_id · landing_page
facebook_campaign_id + facebook_campaign_name
facebook_adset_id    + facebook_adset_name
facebook_ad_id       + facebook_ad_name
facebook_form_id · facebook_lead_id · facebook_page_id · facebook_platform · facebook_created_time
```

כלומר **הנתונים נאספים כבר היום ופשוט נזרקים לפח** — האגרגציה מקבצת רק לפי מקור וקמפיין
ומתעלמת לגמרי מ-Ad Set ומודעה. זה אומר שחלק גדול מ-Drill Down עד רמת מודעה אפשר לבנות
**בלי שום גישה חיצונית ובלי להמתין לאף אישור**, וגם רטרואקטיבית על ההיסטוריה.

## 3. מה חסר — פער מול הבקשה

### 3.1 הוצאות פרסום — הפער הקריטי
טבלת `marketing_costs` קיימת ונקראת ע"י `getDashboardStats`, אבל:
- **אין שום מסך שכותב אליה** — לא בהגדרות, לא בשיווק, לא בעדכון מרוכז
- אין שום מייבא, אין שום חיבור ל-API

→ **בפועל היא ריקה. הוצאה = ₪0. לכן CPL / CAC / ROAS / ROI מוצגים כאפס או `—`.**

### 3.2 אין ולו חיבור אחד לפלטפורמת פרסום
סריקה של כל הקוד: אין Meta Marketing API, אין Google Ads API, אין GA4, אין TikTok,
אין Conversions API. אפס. (האינטגרציות הקיימות במערכת: Voicenter, GreenAPI/WhatsApp,
HYP, SMS 019, Firebase.)

### 3.3 מדדי ה-KPI — 8 מתוך 15

|---|---|
| הוצאה כוללת | 🟡 יש שדה, תמיד 0 |
| מספר לידים | ✅ |
| CPL | 🟡 מחושב, אבל 0 |
| לידים איכותיים | ❌ אין הגדרה ואין שדה |

| פגישות / הגעות | ❌ יש סטטוס "יגיע לסניף" (כוונה) — אין תיעוד הגעה בפועל |

### 3.4 טבלת ביצועים — 7 מתוך 15 עמודות
חסרות: סטטוס פעיל/כבוי (דורש API), לידים איכותיים, % לידים איכותיים,
פגישות/הגעות, הצעות, רווחיות.

### 3.5 Drill Down
קיים: מקור → לידים.
חסר: פלטפורמה → קמפיין → Ad Set → מודעה → לידים ועסקאות. כלומר 3 מתוך 4 הרמות.

### 3.6 פילטרים
- חסר preset **"חודש קודם"** (יש `getPreviousDateRange` ב-`src/utils/dateRange.js`, לא מחובר)
- חסרים פילטרים לפי פלטפורמה / קמפיין / Ad Set / מודעה — יש רק dropdown מקור אחד
- **אין השוואת תקופה מול תקופה קודמת** בממשק (הלוגיקה קיימת, לא מחוברת)

### 3.7 דיווח חזרה לפלטפורמות — 0%
אין outbox, אין triggers, אין CAPI, אין Offline Conversions. סעיף 8 בבקשה חסר לחלוטין.

### 3.8 פערי מודל נתונים
- השדות הם **Meta-centric** (`facebook_*`). לגוגל נשמר רק `gclid` — אין campaign/ad_group.
  צריך עמודות ניטרליות: `ad_platform`, `ad_campaign_id`, `ad_set_id`, `ad_id`…
- `leads.source` הוא טקסט חופשי עם **מעל 100 ערכים שונים** בשתי שפות
  (ראו התיעוד ב-`src/constants/sourceChannels.js`) — עובד לצביעה, שביר כמפתח ייחוס
- `marketing_costs` בצורתה הנוכחית (מקור/קמפיין/סכום) לא יכולה להחזיק הוצאה
  יומית ברמת מודעה — צריך fact table אמיתי

## 4. הארכיטקטורה המוצעת

```
┌─ Layer 5 ── דיווח חזרה ────────────────────────────────────────────┐
│  marketing_events_outbox → pushConversions → Meta CAPI / Google    │
│  Offline Conversions / TikTok Events API                            │
├─ Layer 4 ── UI ────────────────────────────────────────────────────┤
│  Marketing.jsx (שכתוב) — KPI Header · Drill Breadcrumb ·           │
│  PerformanceTable (אגנוסטית לרמה) · Filters · Ad Detail            │
├─ Layer 3 ── אגרגציה ───────────────────────────────────────────────┤
│  marketing_performance_v2(start, end, level, parent_id, filters)   │
│  marketing_kpis_v2(...)  ← נקרא פעמיים להשוואת תקופות              │
├─ Layer 2 ── נרמול Attribution ─────────────────────────────────────┤
│  trigger על leads → עמודות ניטרליות · join ל-ad_entities · backfill │
├─ Layer 1 ── מחברים ────────────────────────────────────────────────┤
│  syncMetaAds · syncGoogleAds · syncTikTokAds · syncGa4              │
│  (Edge Functions, מתוזמנות ב-GitHub Actions cron)                   │
├─ Layer 0 ── מודל נתונים ───────────────────────────────────────────┤
│  ad_accounts · ad_entities · ad_spend_daily · leads(+attribution)   │
│  marketing_costs (נשאר — לערוצים אופליין וריטיינרים)                │
└─────────────────────────────────────────────────────────────────────┘
```

### טבלאות חדשות
- **`ad_accounts`** — פלטפורמה, מזהה חיצוני, שם, מטבע, סטטוס, הפניה לסוד
- **`ad_entities`** — מראה של היררכיית הפרסום: `level` (campaign/adset/ad), `external_id`,
  `parent_external_id`, `name`, `status` (פעיל/כבוי — כאן מגיעה העמודה החסרה בטבלה)
- **`ad_spend_daily`** — `(date, platform, ad_id)` ייחודי; spend, impressions, clicks,
  platform_leads, currency. זה ה-fact table שכל המספרים הכספיים יושבים עליו
- **`marketing_events_outbox`** — תור אירועים לדיווח חזרה, עם retry ו-dedup

### עקרון מנחה ל-UI
RPC אחד מחזיר **אותה צורת שורה** בכל רמה. לכן הטבלה נכתבת פעם אחת, ו-Drill Down הוא
רק קריאה חוזרת עם `level` ו-`parent_id` אחרים. זה מה שהופך את סעיף 5 מפרויקט לפיצ'ר.

### מקור האמת (סעיף 9 בבקשה)
- **הוצאה** — אך ורק מ-`ad_spend_daily` (API) או `marketing_costs` (אופליין, ידני מפורש)
- **לידים, סטטוסים, עסקאות, סכומים** — אך ורק מטבלאות ה-CRM
- אף מספר לא מחושב ידנית ואף מספר לא נשמר בשני מקומות

## 5. גישות ואישורים שנדרשים ממך

### Meta (Facebook / Instagram)
- הרשאת **Admin ב-Business Manager**
- יצירת **System User** ב-Business Settings + הקצאת חשבונות הפרסום אליו
- Token עם `ads_read`, `business_management` (+`leads_retrieval` אם נמשוך לידים ישירות)
- **Ad Account ID** (`act_XXXXXXXXX`) לכל חשבון
- לדיווח חזרה: **Pixel ID** + **Conversions API Token**, ו-**Offline Event Set / Dataset ID**
- אפליקציה ב-Meta for Developers (App ID + Secret)

### Google Ads
- הרשאת Admin ל-MCC או לחשבון
- ⚠️ **Developer Token** מ-API Center — **אישור Basic Access לוקח בין ימים לשבועיים.
  זה הפריט עם זמן ההמתנה הארוך ביותר. כדאי להגיש בקשה היום.**
- OAuth2 Client ID + Secret (פרויקט Google Cloud) + Refresh Token
- **Customer ID** (10 ספרות) + `login-customer-id` אם תחת MCC
- לדיווח חזרה: Conversion Action מסוג Offline Import + לכידת `gclid` בכל דפי הנחיתה

### Google Analytics 4
- **Property ID**
- Service Account כ-Viewer על ה-Property + הפעלת GA4 Data API
- (GA4 = תנועה והתנהגות. **ההוצאה מגיעה מ-Google Ads, לא מ-GA4**)

### TikTok
- הרשאת Admin ב-TikTok Business Center
- אפליקציה ב-TikTok for Business (App ID + Secret) → OAuth → Access Token
- **Advertiser ID**
- לדיווח חזרה: Events API Token + Pixel ID

### Taboola / Outbrain (שלב מאוחר)
- Taboola Backstage: `client_id` + `client_secret`
- Outbrain Amplify: user/password → token, ו-Marketer ID

### תשתית (מצידנו)
- Supabase Function Secrets לכל פלטפורמה
- מיגרציות חדשות + workflow תואם לכל אחת
- ⚠️ כל Edge Function חדשה **חייבת להתווסף ידנית לרשימה ב-`deploy-functions.yml`**
- GitHub Secrets ל-cron workflows

### תהליך שיווקי (לא קוד, אבל קריטי)
- **תקן UTM אחיד בכל קמפיין בכל פלטפורמה.** בלי זה אי אפשר לקשור ליד מגוגל/טיקטוק למודעה
- לכידת `gclid` / `fbclid` / `ttclid` בכל טופס בדף נחיתה והעברתם ל-`upsertLead`

## 6. החלטות עסקיות שאני צריך ממך לפני הקוד

אלה לא שאלות טכניות — כל תשובה כאן משנה כל מספר בדשבורד:

1. **מהו "ליד איכותי"?** סטטוס מסוים? סימון של הנציג? ליד שענה לטלפון? עומד בתקציב?
2. **מהי "פגישה / הגעה"?** היום יש רק סטטוס "יגיע לסניף" — כוונה, לא הגעה.
   האם מתועד בפועל מי הגיע? אם לא, צריך להוסיף תיעוד ולשנות תהליך עבודה לנציגים.
3. **מודל ייחוס** — Last Click או First Touch?
4. **לאיזה תאריך שייכת עסקה** — לתאריך כניסת הליד או לתאריך ההזמנה?
   (משנה לחלוטין את ה-ROAS של כל חודש)
5. **חלון ייחוס** — 7 ימים? 28? מה עם ליד שנסגר אחרי 3 חודשים?
6. **הכנסה** — כולל או ללא מע"מ? לפני או אחרי ביטולים והחזרות?
7. **הוצאה** — הפלטפורמות מדווחות ללא מע"מ. להשוות ככה או להוסיף?
8. **מטבע** — האם חלק מהחיוב בדולרים? (Meta לעיתים)
9. **בעלות על חשבונות הפרסום** — שלנו או של סוכנות? גישת סוכנות משנה מהותית את סיפור הטוקנים.

## 8. סיכונים שכדאי לדעת עליהם מראש

- **פער בין הפלטפורמה ל-CRM** — מספר הלידים שמטא מדווחת עליו לעולם לא יהיה זהה למספר
  ב-CRM (5–20% פער זה נורמלי: כפילויות, טפסים שנשרו, חסימות). הדשבורד יציג את שני
  המספרים ואת **אחוז ההתאמה**, כדי שלא ניתן אמון עיוור בחיבור שנשבר בשקט.
- **פרטיות ו-iOS** — מטא מסתירה נתונים ברמת מודעה כשהנפחים קטנים מדי.
- **Developer Token של Google** — סיכון לוח זמנים אמיתי. להגיש בקשה מיד.
- **היסטוריה** — Backfill מ-`facebook_*` יחזיר ייחוס היסטורי מלא ל-Meta.
  להיסטוריית **גוגל אין ייחוס מתחת לרמת הקמפיין** — הנתון פשוט לא נשמר. מכאן והלאה כן.
- **`deploy-functions.yml`** — רשימת הפונקציות מפורשת. פונקציה חדשה שלא נוספה לרשימה
